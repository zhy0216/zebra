# P0 · Zod 3 升级到 Zod 4

条目 id：`ZOD-1`

状态：`pending`

## 问题

多个 workspace、示例和测试仍声明 Zod 3；`@zebra/schema-zod` 还依赖 Zod 3 的 `ZodTypeAny` 和旧 JSON Schema 转换器。单纯改依赖版本会破坏类型检查，甚至让 MCP `inputSchema` 静默变成空对象，因此需要把依赖图、adapter 和 Standard Schema 边界一起迁移。

## 实现思路

1. 先列出所有直接 Zod 使用点和 manifest：根包、`packages/client`、`contract`、`core`、`mcp`、`schema-zod`、`testing`，以及 `examples/contract-blog`、`examples/forum`。统一到 Zod `4.x`，用 Bun 重新生成锁文件，不手工编辑版本号。
2. 检查 Zod 4 的 Standard Schema 实现与当前 vendored `StandardSchemaV1` 类型。把注释中“zod v3 专属”的假设改成 Zod 4/标准协议事实，但不要复制第二套协议或让 core 产生 Zod runtime dependency。
3. 重写 `packages/schema-zod/src/index.ts` 的类型边界，移除 `ZodTypeAny`。优先评估 Zod 4 原生 `z.toJSONSchema(schema, { target: "draft-7", io: "input" })`；若保留 `zod-to-json-schema`，必须用真实 Zod 4 runtime 证明每种 schema 都能正确转换，不能只依赖 peer range。
4. 保留 adapter 的公开行为：`SchemaAdapter`/`SchemaOverride` API、override first-match、draft-7 目标、移除顶层 `$schema`、MCP 需要的输入形状。对 transform、coerce、default、optional、unsupported schema 明确选择 input/output 语义；不能转换时稳定报错或要求 override，绝不返回空 schema。
5. 更新并扩展测试：嵌套 object、array、union、enum、literal、record、nullable、coerce、default/optional、transform input、手工 override、无 `$schema`，以及至少一个 MCP tool 的实际 `inputSchema`。如果 Zod 4 原生输出增加合法约束（例如 number 边界或 required 规则），按公开契约重新断言并说明原因，不硬编码旧转换器的错误输出。
6. 跑 core/contract/client/testing/MCP 和两个 Zod 示例的 runtime/type tests，确认 params/query/body/output 推导、issue path、客户端请求和发布入口仍然成立。检查打包后的依赖隔离，确保 `@zebra/core` 不因测试依赖变成运行时 Zod 依赖。
7. 依赖图允许第三方包存在自己的 peer 版本，但本仓库的直接声明、示例和 workspace 解析必须走 Zod 4；记录任何不可避免的 transitive Zod 3 及其原因。

## 涉及文件（初始所有权）

- manifests：`package.json`、`packages/client/package.json`、`packages/contract/package.json`、`packages/core/package.json`、`packages/mcp/package.json`、`packages/schema-zod/package.json`、`packages/testing/package.json`、`examples/contract-blog/package.json`、`examples/forum/package.json`；
- `bun.lock`；
- `packages/schema-zod/src/index.ts`、`packages/schema-zod/test/schema.test.ts`、`packages/mcp/test/mcp.test.ts` 及受影响的 contract/client/core/testing type/runtime tests；
- Zod/Standard Schema 相关注释和示例代码；不修改与 schema 迁移无关的业务逻辑。

## 验收条件

- 所有直接 manifest 都是 Zod 4，锁文件可由 Bun 1.4 以 frozen 模式安装；没有本仓库直接声明的 Zod 3。
- Zod 4 的 schema adapter 不再引用 Zod 3-only 类型，不会对合法 schema 静默返回空 JSON Schema；MCP `inputSchema` 可实际消费。
- adapter、MCP、contract、client、testing、core 相关测试和 type tests 通过，且 `bun run build` 通过。
- `@zebra/core`、`@zebra/contract` 等只依赖 Standard Schema 结构，不新增 Zod runtime import。

## 验证命令

```sh
bun install --frozen-lockfile
bun test packages/schema-zod packages/mcp packages/contract packages/client packages/testing packages/core
bun run typecheck
bun run build
bun run verify:packages
```

## 风险与处理

- Zod 4 原生 JSON Schema 与旧转换器的输出细节不同，尤其是 transform、coerce、default、optional 和 number 边界。以 MCP/codegen 的输入 schema 契约为准，记录每个有意变化。
- `zod-to-json-schema` 可能声明支持 Zod 4 但在特定 schema 上产出空结果；必须有运行时回归测试和 unsupported-schema 处理。
